Tempertime

Backend de una aplicación para organizar eventos en grupo, desarrollado en solitario. Una persona crea un espacio de trabajo, invita a otras con un código y les asigna eventos con fecha y hora. Cada miembro ve solo los eventos que le corresponden, filtrados por día, semana o mes en su propia zona horaria.

Qué incluye: registro e inicio de sesión, gestión de espacios de trabajo y miembros, roles (dueño y miembro) con permisos distintos, invitaciones por código y eventos para todo el grupo o para personas específicas.

Seguridad: autenticación con JWT (un token firmado que identifica al usuario) y refresh tokens con rotación y revocación, guardados como hash SHA-256. Contraseñas con BCrypt. Códigos de invitación protegidos con SHA-256 y cifrado AES/GCM. Control de acceso por rol dentro de cada espacio de trabajo.

Cómo está hecho: API REST con 32 endpoints en Java 17 y Spring Boot 3, con Spring Security, Spring Data JPA, Hibernate y MySQL. Arquitectura en capas organizada por dominios, DTOs con MapStruct, validaciones, paginación, filtros y manejo global de errores con 44 códigos. Las fechas se guardan en UTC y se consultan según la zona horaria del usuario.

Calidad: 531 tests automatizados (unitarios, de repositorio, de controladores y end-to-end) con JUnit 5 y Mockito, documentación con OpenAPI/Swagger y un manual técnico de 55 páginas.

JobLens

Backend de una aplicación para organizar una búsqueda de empleo, en desarrollo. Una persona se registra, sube su CV en PDF y crea procesos de búsqueda con sus criterios (puesto, tecnologías, ubicación, modalidad), y el sistema guarda el historial de esos criterios. Cada proceso muestra sus ofertas con puntuación, con orden, paginación y favoritos. La integración con inteligencia artificial está prevista y aún no está implementada.

Seguridad: JWT con refresh tokens con rotación; si se reutiliza uno ya revocado, se cierran todas las sesiones del usuario. Los tokens se guardan como hash SHA-256 y las contraseñas con BCrypt. Cada usuario solo accede a sus datos: la API usa identificadores UUID y responde el mismo 404 ante un recurso inexistente o ajeno, para no filtrar información.

Subida de CVs: valida la firma del PDF, rechaza PDFs cifrados, limita tamaño, páginas y texto, protege contra path traversal (acceso a carpetas no permitidas) y extrae el texto con PDFBox.

Cómo está hecho: API REST con 26 endpoints en Java 21 y Spring Boot 4, con Spring Security, Spring Data JPA, Hibernate, PostgreSQL, Flyway y Docker Compose. Monolito modular (módulos separados dentro de una misma aplicación) que se comunican solo por interfaces públicas.

Calidad: 688 tests automatizados (unitarios, de repositorio, de controladores y de flujo completo), con más de 140 contra PostgreSQL real mediante Testcontainers. Desarrollado con Claude Code como asistente.
